\paragraph{What is timed.}
Each tool is run in its own process on one case. A \emph{cold} time is the wall-clock time of a process from launch to exit,
as a user of the command line sees it: start-up, JIT compilation and reading the input included. A \emph{warm} time is the
median of \TODOnum{trials} timed computations after \TODOnum{warm-ups} untimed ones in one process; a computation longer than
a cutoff is reported once and used for both. One engine runs per JVM, since JIT state leaks between engines. Inputs that a tool reads in
its own format (DIPHA, PHAT, RedZeD) are converted beforehand and not timed; the harness records that the input is not the
same file. A \emph{kernel} row (PHAT) times a reduction of a prebuilt matrix and builds no complex, so it is never the
baseline against which another tool is measured.

\paragraph{Memory.}
Peak memory is the process's own high-water resident set size, sampled while it runs; for a JVM the harness also records the
peak of the heap pools. The JVM runs with a serial collector and a heap that follows live data, so that resident memory is
close to what a computation needs; a fixed large heap would instead measure the total allocation, which is a property of the
garbage collector. The maximum heap is \TODOnum{size}.

\paragraph{Threads.}
The main tables are single-threaded, as ripser.cpp, RedZeD and GUDHI are: every \tdaj{} row runs with the library's parallel
steps sequential. Rows that use every processor say so (``\code{-mt}'') and are reported separately
(\cref{sec:eval-threads}).

\paragraph{Fields.}
Vietoris--Rips tables are over $\Ftwo$, which every tool supports except OAT (rationals). We also report \tdaj{} and the tools that
support other primes at $p=17$, the library's default. A tool that does not support a case or a field reports ``--''.

\paragraph{Failures.}
Timeouts (\TODOnum{timeout}), memory limits and out-of-memory kills are results and are never dropped: a table cell shows
\code{T/O}, \code{OOM} or \code{limit}. A limit of another tool is a result of its own; for instance, ripser.cpp's
coefficient builds fail above a simplex index of $2^{55}-1$.
\VERIFY{this limit was read in the copy of ripser.cpp inside the ripser.py 0.6.15 sdist, not in the pinned commit}

\paragraph{Agreement.}
Before a time is reported, the run's barcode is compared with the reference's by bottleneck distance per degree
(\cref{sec:agreement}); a disagreement is marked and the row is left out of the means.

\paragraph{Cases.}
\Cref{app:benchmark} lists the cases. The Vietoris--Rips cases are the seven of the Ripser paper's own benchmark
with its flags (minus the printing filter), plus a size ladder on the three-sphere and cyclooctane. These cases favour Ripser,
whose authors chose them; we use them because they are the common ground on which every tool in the comparison
has been run before.

\subsection{Threats to validity}\label{sec:threats}

\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
\item \emph{One machine, one commit, one pinned version of each tool.} Ratios between tools depend on the machine's cache and memory system.
\item \emph{The cases.} They come from the Ripser paper's benchmark and the PH roadmap, so they favour Ripser; cases where \tdaj{}'s generality
  matters (other fields, other complexes, representatives) are in other tables, and a reader should weigh each table for its question.
\item \emph{Precision.} ripser.cpp, Dionysus and RedZeD compute with single-precision values; \tdaj{} uses doubles; the agreement
  tolerance accounts for it, and the memory ratios do not correct for it.
\item \emph{The $V$/$T$ mismatch for images.} \tdaj{}'s $V$ rows run on a refined image; the table says so.
\item \emph{Who wrote the harness.} The harness is ours. It follows the Ripser paper's own benchmark where one exists, and records flags, versions and failures;
  it is public, so each row can be rerun.
\item \emph{The JVM.} Cold and warm times are different quantities; compact heap policy is chosen to measure live data. We report both times and the heap policy.
\item \emph{Representatives.} We measure validity and cost, not usefulness, and tools that return no representative cannot be compared on them.
\end{itemize}
